# 订单工单侧栏与版本发布记录设计

## 目标

让后台“订单工单”的父子关系一眼可辨，并把之后的本地版本整理和线上更新记录成可追踪、可复用的流程。每次版本报告沿用用户确认的格式，清楚区分 Git 版本、测试结果、代码内容和部署状态。

## 当前依据

- 本地 Bobo 仓库位于 `D:\波波本地联调`；当前检查使用同一项目的 `feature/platform-delivery` 工作树。
- 现有标签 `bobo-v0.3.0-platform-integration` 指向提交 `26d8bf9`。
- 当前功能分支在该标签之后增加了平台来源订单看板和配送生命周期，当前 HEAD 为 `b1f78f3`。
- 订单工单侧栏包含“全部订单”“工厂单”“平台单”三个独立页面；生产总览上的同名按钮是看板数据范围筛选。
- 当前待正式创建的平台单数量只显示在“平台单”子项。父项没有同步角标。
- 代码版本字段、Git 标签和功能分支进度需要在后续发布中明确对应，不能把候选代码描述为已部署版本。
- 项目现有说明记录线上使用宝塔/PM2 与 MySQL `app_state.main`。另一份安全发布设计提到 `/srv/bobo` 和 systemd；在核对真实线上目录和进程前，不采用后一组路径编写可执行部署命令。

## 侧栏导航

- “订单工单”作为非路由分组标题，下面包含“全部订单”“工厂单”“平台单”三个页面入口。
- 分组标题与“平台单”子项显示相同的待正式创建平台单数量。该数量只统计 `creationStatus === "pending"` 的平台来源工单。
- 三个子项采用明确缩进、连接线和当前项高亮，显示它们属于同一菜单组；分组标题自身不伪装成当前页面，也不触发页面切换。
- 生产总览上的来源按钮保留筛选功能，并增加清楚的组名“看板订单范围”。切换这些按钮只改变看板，不改变侧栏所在页面。
- 保持现有角色权限：纯司机不显示订单工单组；其他角色按现有权限规则显示。

## 版本标识和版本报告

- 继续使用语义化版本 Git 标签：`bobo-v<major>.<minor>.<patch>-<feature>`。
- `package.json` 版本号、版本标签、主仓库提交号和小程序提交号（如本次修改涉及小程序）须在版本报告中分别列明，不得互相替代。
- 版本标签只在该版本范围确定、相关检查完成、目标提交已提交后创建。开发分支中的后续提交不得沿用旧标签声称已包含在该版本。
- 每次版本报告采用以下格式，并按真实结果填写；不适用的项目写“无”，未部署的环境明确写“未部署”：

```text
已整理成 Git 新版本，未触碰旧线上副本，也未部署。

- 主仓库提交：<短提交号>
- 小程序提交：<短提交号或无>
- 版本标签：<标签>
- 完整串行测试：<通过数>/<总数> 通过，或未运行及原因
- 本地工作区：干净 / 尚有未提交修改
- 旧线上副本：未修改 / 状态及依据
- 测试域名和正式域名：未部署 / 实际部署版本

本版本包含：
- <功能变更>

安全发布脚本与备份/回滚机制：已实施 / 尚未实施；说明剩余操作。
```

- 只有确实检查过旧线上目录和部署环境，才报告“未修改”；否则标注“未核查”。
- 只有实际完成测试或部署后才填写相应成功状态，不根据历史结果推断当前通过。

## 发布包边界

- 后续代码发布包必须从确定的 Git 提交或标签生成，不压缩工作目录。
- 发布包排除 `data/`、`db/`、`public/uploads/`、本地配置、密钥、日志、缓存和其他运行时数据。
- 发布清单记录版本标签、完整提交号、构建时间和包文件 SHA-256。
- 本设计只规范本地版本整理和代码发布包；不新增服务器连接、文件传输、宝塔操作、PM2 重启或 MySQL 写入步骤。
- 线上运行模型和实际部署目录核对完成前，线上更新仍按用户确认的人工操作清单执行。任何线上部署均须另行获得明确授权。
- 旧线上副本 `D:\codex内容\copy黑湖小工单` 保持冻结，不从该目录复制业务数据或上传文件到本地版本。

## 实施范围

1. 调整 `public/app.js` 的订单工单分组语义和待创建角标。
2. 调整 `public/styles.css` 中子菜单缩进、层级和选中状态。

4. 对照实际仓库和部署说明，整理版本号、标签和发布报告格式；不创建与真实 PM2/MySQL 部署配置冲突的线上自动部署脚本。
5. 补充本地版本发布操作说明，列清版本整理、纯代码包、包校验及人工部署状态的记录方式。

## 验收标准

- 订单工单父项清楚呈现为分组标题，三个子页面有明确层级与当前项状态。
- 父项和平台单子项角标取同一个待创建平台单计数。
- 生产总览来源筛选清楚标注为看板范围，且不会与侧栏子页面混淆。
- 版本报告字段和顺序与本设计示例一致，区分提交、标签、测试和部署状态。
- 版本说明不把未核实的 `/srv/bobo`/systemd 方案当作线上现状。
- 发布流程明确排除业务数据库、上传附件、密钥和本地配置；本次不执行线上部署。
