# 订单工单侧栏与版本发布流程实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让订单工单的三个子页面层级清晰、父子角标一致，并建立可追踪的本地版本整理与纯代码包流程。

**Architecture:** 沿用现有订单来源筛选和角色权限，只调整导航呈现；发布工具只从干净 Git 标签构建归档包，输出版本清单和 SHA-256，不连接或修改线上环境。

**Tech Stack:** Node.js、现有前端 JavaScript/CSS、PowerShell、Git。

**Spec:** `docs/superpowers/specs/2026-09-25-order-menu-and-versioned-release-design.md`

## 全局约束

- 不访问或修改旧线上副本 `D:\codex内容\copy黑湖小工单`。
- 不执行线上部署、服务器连接、PM2 重启或数据库写入。
- 发布包从已提交的 Git 标签生成，不从工作目录打包。
- 排除数据库、上传附件、本地配置、密钥、日志、缓存和运行时文件。
- 版本报告只写本次实际核实的提交、标签、测试和部署状态。
- 不在本次实施中创建或执行自动化测试；不声称未经验证的通过结果。

## 人工验收重点

1. 管理者可见“订单工单”分组标题及三个缩进子项，父级与“平台单”角标数量一致。
2. 当前子项高亮；切换子项只进入对应订单页，父级标题不触发路由。
3. 纯司机权限仍不显示订单工单导航；生产总览来源按钮明确标注为看板范围。
4. 发布工具只接受已存在的标签和干净工作区，并拒绝包含运行时数据或敏感配置的归档内容。
5. 发布说明中的版本报告字段顺序与用户确认格式一致；未部署状态明确标记。
